# FluffyMachines 26.2.14

## Auto-crafter recipe-cache lifecycle

The existing cache could retain a negative result after additional recipes were registered, or keep a positive result after the provider recipe count decreased. Its index refresh was reached only after a cache miss. The crafter now checks the provider's existing size-based index generation before consulting either cached result. Indexes and machine results are published together, so a resolver retaining an older generation cannot repopulate the current cache. Clearing an enabled machine's input grid also discards its cached template, including when unpowered.

Unchanged recipe sets keep their index and per-machine results. This is not a per-machine full recipe scan and does not add a crafting delay or change energy costs. Same-size in-place recipe edits and unsynchronized provider mutations are not detected by the existing provider-size contract; no universal hot-reload or Folia-concurrency guarantee is made.

## Preservation boundary

Existing input/output slots, recipe ordering/matching, ingredient consumption, retained-template and one-shot rules, energy use/capacity, IDs, persistent keys, world data and migration defaults are unchanged. The completed 26.2.13 barrel/storage/hover/frame work remains intact. The older PR8 performance branch is preserved; its obsolete versions and alternate idle shortcut are not merged wholesale.

## Validation

The staged full project passed 33 tests (20 existing barrel checks and 13 cache-policy regressions) against each retained Paper 1.21.11, 26.2 and 26.3 API lane with the checksum-verified published Legacy 4.1.64 core. The cache-policy tests use explicit values; real machine and restart checks are separate. The final distributable is rebuilt against the 1.21.11 API with Java 21 bytecode. Publication and the canonical addon bundle remain independent gates.
