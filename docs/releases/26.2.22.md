# SF_FluffyMachines v26.2.22 — Cargo input identity visibility

Distinct release candidate following published [v26.2.21](https://github.com/wickidcow/SF_FluffyMachines/releases/tag/v26.2.21). This version is not published until exact-head CI and master publication gates pass.

## Changes

- When the stored item identity and items physically awaiting admission in Cargo input slots do not match the existing strict material, Slimefun ID, typed PDC and Adventure metadata policy, the Barrel GUI shows an orange **Cargo input identity mismatch** pane instead of a misleading green status.
- The warning reports the actual total in saved reserve plus both output slots, and separately shows the pending incompatible input quantity. A zero saved reserve is legitimate when outputs contain all stock.
- This is **display-only**. No identity normalization, source item rewrite, Cargo consumption, storage/persistence counter mutation, owner/PDC mutation, QuickShop change or ID-only merging.

## Native regression gates

- Real CargoNetworkTask routing of 64 + 31 registered items must yield **95** stored units, with green GUI status and two outputs totaling 95 even if the reserve is zero.
- Real Paper native historical/current fixture must retain **37 old units in output** and **12 new units in input** on noncosmetic Adventure difference at the same Slimefun ID, and show the orange rejection warning without changing either count.
- Compare both ItemStack serialized byte sequences before/after display refresh and assert typed owner STRING and custom quantity LONG PDC are preserved.
- Re-run the full Maven build, native Paper 1.21.11, 26.2 and 26.3, Cargo restart, backpack, release provenance and immutable-tag safety gates. The current historical fixture is synthetic: it is not proof of live AlbionMC historical serialization.

## Deployment and limits

Back up saved worlds, block data and inventories. Install only the official distinct-tag raw SF_FluffyMachines26.2.22.jar after its SHA-256 has been verified, retaining v26.2.21 as rollback. Compare true total output quantities and physical pending input before treating a zero reserve as loss. This is not a general old/new item stacking repair: meaningful name/lore/model/typed PDC identity differences remain fail-closed until a source-specific proof exists.
