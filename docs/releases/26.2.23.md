# SF_FluffyMachines v26.2.23 — read-only Cargo/Barrel Doctor quantity provenance

Distinct successor to the unchanged [v26.2.22](https://github.com/wickidcow/SF_FluffyMachines/releases/tag/v26.2.22).

## Why

A saved Fluffy Barrel reserve of **zero** is not evidence that Cargo lost its deposited items. Cargo may have placed all of them into the two *physical* output slots. The current native registered Cargo tests confirm an exact 64 + 31 = **95 items** in outputs with saved reserve **0**. A separate same-ID old-versus-fresh Adventure metadata pair can also leave **37 historical units** in output and **12 fresh units** still pending in input. They must never be silently merged.

## Addon Doctor improvement

- When Slimefun Legacy invokes its connected FluffyMachines Doctor, inspect only already loaded barrel menus via the same strict producer identity predicate used by the actual barrel. No new scanning outside loaded chunks, background work, persistent keys, commands, config toggles or item mutations.
- When saved reserve equals zero but matching physical outputs contain stock, report a **read-only informational count** and up to four bounded example locations. It is **not** a Doctor issue or evidence of lost items.
- When an output template conflicts with the saved registered item, report the conservative existing reason without inventing an item identity or quantity. When genuinely incompatible Cargo input remains pending, report the actual pending quantity separately, without consuming it or treating shared Slimefun ID as equality.
- Keep all earlier fail-closed handling for invalid persisted counts, missing registered display template and the guarded Mini Barrel capacity repair. Do not modify old items, physical outputs, typed PDC, storage ledgers or QuickShop templates. The read-only Doctor additions perform **no repair**, even if an administrator invokes the preexisting repair command.

## Native and unit regression

- Java unit tests cover identity-verified 64+31 outputs at saved zero, distinct 37-old/12-fresh metadata, unknown/nonzero reserve, unsafe output identities, and immutable input values.
- Extended actual Paper native `CargoNetworkTask` and historical-item scenarios invoke the production `FluffyDoctor.run(false)` on the loaded barrels. They require correct read-only output-only and pending-mismatch receipts while comparing physical old/new serialized bytes and persisted reserve before/after the Doctor. Existing independent restart and Cargo conservation checks remain required.
- Release only after exact-head Maven build, Java 21 raw JAR validation, Paper 1.21.11 / 26.2 / 26.3 native Cargo and backpack tests, restart, strict source/asset checks, successful merged-master CI and a distinct **v26.2.23** tag/raw `SF_FluffyMachines26.2.23.jar` SHA-256 proof. Never overwrite v26.2.22.

Do not treat an issue-free report as a blanket certification for old items or Folia/other database backend behavior. Continue [Fluffy issue #48](https://github.com/wickidcow/SF_FluffyMachines/issues/48) and coordinate typed-identity findings with [Slimefun Legacy core issue #615](https://github.com/wickidcow/Slimefun-Legacy/issues/615).
