# SF_FluffyMachines v26.2.21 — Fail-closed historical Barrel Doctor safety

Distinct new release following immutable [v26.2.20](https://github.com/wickidcow/SF_FluffyMachines/releases/tag/v26.2.20). This is a **storage-integrity hotfix**; it does not alter ordinary barrel transfers, recipes, quantities, machine rates, item IDs, or saved PDC.

## Correctness and conservation

- **Never infer an empty saved reserve from a cosmetic barrier or absent display.** Older Doctor repairs could treat an invalid or missing `stored` counter plus a blank display as grounds to reset `stored=0`. Such a rewrite could discard the only known historical quantity. Now even an **explicit Doctor repair** refuses that write: it reports an unverifiable historical reserve and directs the admin to backed-up manual investigation.
- **Mini Barrel capacity correction is conditional on a verified saved amount.** When `max-size` is malformed or exceeds configured bounds, Doctor only corrects the capacity if a nonnegative persisted `stored` quantity is known and the configured maximum is positive. It never reduces capacity below that saved count. If the quantity is unknown, capacity is left untouched.
- No automatic migration, player-item rewrite, PDC normalization, output-slot mutation, or reserve reconstruction was added. A broken historical reserve is still *not* automatically recovered.

## Verification before publication

- Pure JUnit tests cover missing, negative, zero, over-capacity, and max-int stored quantities; safety script now rejects any code path that writes `setData("stored", ...)` from Doctor.
- Native disposable Paper tests include an actual loaded registered barrel whose saved count is deliberately invalid and whose physical output carries registered Slimefun metadata and typed owner PDC. They invoke the real Doctor repair, preserve the unreadable count and all 19 output items, then verify the state and repeat repair in a **separate clean Paper JVM**. This is a synthetic corruption fixture, not an old AlbionMC world.
- Preserve the established native Cargo 64+31 routing, historical old/new item nonmerge, physical barrel outputs, independent server restarts, backpack integrity, Watering Can charge and Paper 1.21.11/26.2/26.3 checks.
- Raw `SF_FluffyMachines26.2.21.jar` must be compiled from the exact merged master SHA, target Java 21 bytecode, pass shaded plugin identity checks, and match the new immutable release's official SHA-256 digest. The existing master publisher rejects pre-existing tags/releases and verifies the downloaded official raw JAR. **Do not publish unless exact-head CI and post-merge master are green.**

## AlbionMC installation and spot checks

1. Stop server, back up worlds, configs, Slimefun block data and machine contents. Keep v26.2.20 untouched as rollback.
2. Install only the official raw JAR; remove the previous JAR to prevent double-loading. No config setting needs enabling for the Doctor safeguard.
3. On a backed-up clone with suspicious historical barrels, inspect stored counter, display identity, both output slots and typed PDC **before** any Doctor action. Run Doctor scan, then explicit repair; verify any unknown count stays unknown and the output quantity and owner tags do not change. Use backed-up manual recovery for uncertain old reserves.
4. Recheck valid Mini Barrel capacity and real Cargo deposits/withdrawals, full output buffers, Watering Can protected-region uses and clean two-boot persistence.
5. Live historical AlbionMC item acceptance, Purpur native runtime, protected regions and third-party network integrations are **not proven** by automated native fixtures. Report any issue in a subsequent version; never turn this conservative safety gate into an automatic zero migration.

The Slimefun-Legacy core/v81 ZIP and SlimefunUnified are maintained by separate tasks and are not modified by this release.
