# SF_FluffyMachines v26.2.24 — verified Cargo/Barrel input accounting

Distinct successor to the unchanged [v26.2.23](https://github.com/wickidcow/SF_FluffyMachines/releases/tag/v26.2.23), carrying the production fix merged from [PR #51](https://github.com/wickidcow/SF_FluffyMachines/pull/51). Original FluffyMachines credits remain with NCBPFluffyBear.

## Gameplay fix: no unverified storage credits

- Fluffy Barrel now compares the **actual physical input slot** immediately before and after the void-returning `BlockMenu.consumeItem` call. A request to consume `N` items is **not** treated as proof that `N` were removed.
- The saved barrel reserve increases only by the observed valid quantity decrease, with original item identity checked using `ItemStack.isSimilar` (including Adventure components, typed PDC, owner data and custom metadata).
- A full/partial/no-op consume, invalid amount or unexpected same-ID-but-different-owner replacement does not generate phantom stock. Initial barrel registration creates its display template only after consumption is confirmed.
- Existing matching/legacy cosmetic compatibility is not broadened: this is an **accounting fix**, not an item normalization or cross-version identity migration.

## Native regression evidence

- JUnit exercises full, partial, rejected and invalid input conservation and mismatched metadata.
- A real Paper/Slimefun `BlockMenu` scenario verifies 13 -> 8 physical consumption, source snapshot immutability, stored reserve neutrality, typed owner PDC and final production ticker output of exactly 8.
- A native **virtual item** with the same Slimefun ID but changed typed-owner PDC verifies that the barrel keeps its nine physical items and does **not** credit the saved reserve. Legacy empty-slot behavior is also recorded without allowing phantom credit.
- Existing full native Cargo-network routes, 64 + 31 output buffers, read-only Doctor receipts, restart conservation and historical nonmerge regressions remain required in the CI case sets for Paper 1.21.11, 26.2 and 26.3.
- Publication is gated on same-source verified Maven CI, raw Java 21 JAR/SHA-256 provenance and green `master` CI; **only then** the separate immutable-master workflow can create `v26.2.24` and `SF_FluffyMachines26.2.24.jar`.
