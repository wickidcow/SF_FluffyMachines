# SF_FluffyMachines v26.2.20 — Watering Can and historical barrel diagnostics

A new distinct version following immutable [v26.2.19](https://github.com/wickidcow/SF_FluffyMachines/releases/tag/v26.2.19). Publishing requires a green exact-master build, checked Java 21 JAR, native Paper regression suite, safe source identity and unchanged previous release assets.

## Scope

### Already merged and native tested

- [PR #41](https://github.com/wickidcow/SF_FluffyMachines/pull/41): Watering Can now uses the supported Paper 1.21.11/26.2/26.3 bonemeal sapling path without destructive block replacement or retries.
- A disabled ExoticGarden plant no longer spends water before refusing the interaction.
- Stored negative Watering Can charge cannot be consumed/discharged to create additional charge; explicit water refill recovers it without changing unrelated owner PDC.
- Spruce tree type uses Bukkit `REDWOOD`; unknown exotic tree types fail closed without a charge.
- Native tests cover actual saplings, registered Watering Can charge, PDC and quantity conservation through two Paper boots, and the existing Cargo and backpack regressions.

### Merged read-only diagnostics

- [Merged PR #44](https://github.com/wickidcow/SF_FluffyMachines/pull/44) adds *read-only* Fluffy Barrel diagnostics: a red status now distinguishes invalid saved count, missing registered identity, nonpositive physical output, old/new metadata mismatch and overflow. Its exact combined-head native CI passed before merge. The diagnostic does **not** repair, migrate, combine or rewrite historical barrel data.

## Release verification and expedited rollout

- PR #41 and #44 have both merged; version 26.2.20 release metadata merged as [PR #45](https://github.com/wickidcow/SF_FluffyMachines/pull/45). Test protected/unprotected watering, ExoticGarden, Cargo, two-boot storage and diagnostic display before moving the new JAR to live players. **Native automated tests do not certify every real historical item.**
- Verify the published `SF_FluffyMachines26.2.20.jar` and GitHub tag against the exact master commit and SHA256 before inclusion in the next Slimefun Legacy addon bundle.

This version excludes unsafe automatic old-item migration, IE2 presentation Doctor, AlchimiaVitae crafting fixes, core and SlimefunUnified changes.

## AlbionMC post-release staging and regression checklist

Use a **backup or disposable staging clone** of the relevant world, inventories, and plugin data. Record the exact candidate JAR SHA256, Paper build, Slimefun Legacy version, installed ExoticGarden version, and whether protection hooks are enabled. Do not substitute a synthetic CI result for this record.

| Scenario | Action and required observation |
| --- | --- |
| Protected vanilla sapling | With a non-privileged player and a charged Watering Can, interact inside a region where growth is denied; verify the sapling, surrounding blocks, and charge remain unchanged. Repeat after reconnect. |
| Unprotected vanilla sapling | Interact with an allowed sapling and observe supported bonemeal behavior; check that charge changes only when the interaction is accepted, with no extra consumption on a rejected or no-op interaction. |
| ExoticGarden disabled/denied plant | Interact with a disabled or denied ExoticGarden plant; verify no charge is spent and no block is modified. |
| ExoticGarden allowed plant | Exercise one supported plant in an unprotected area; verify only accepted use consumes charge, and the resulting plant remains valid after restart. |
| Watering Can persistence | Record pre-restart charge, item amount, and unrelated custom PDC, perform two clean server boots, and compare the same item after each boot; no spontaneous charge gain or unrelated metadata changes. |
| Historical Fluffy Barrel | Before interaction, back up the actual historical barrel and record saved count, physical output, owner PDC and Cargo inputs/outputs. Inspect the read-only rejection reason; repeat after two clean boots and a controlled Cargo attempt. The diagnostic itself must not change any stored or physical quantity. |
| Full inventory Quick Withdraw | With two populated machine output slots and extra empty player inventory slots, withdraw and compare total quantities across machine and player inventory before and after; no duplication, loss or silent overwrite. |

For each scenario, attach **PASS/FAIL/UNTESTED**, before/after counts, relevant console messages, and restart evidence to [PR #45](https://github.com/wickidcow/SF_FluffyMachines/pull/45). If the test world or original historical item is unavailable, mark **UNTESTED** and keep the affected feature off the production deployment list until tested. Never upload private player data, full PDC dumps with personal identifiers, or unredacted world backups to a public PR.
